## 192 个 warning 的根本原因

### 原因 1：项目代码大量使用 `let`，但实际从未重新赋值（占 ~140 条）


这是历史代码风格问题：项目早期可能没有 lint 工具，写代码时习惯性用 `let`。只有极少数变量（如 `app.js:22` 的 `_currentTab`）确实需要重新赋值，**真正需要 `let` 的可能只有 1-2 个**。

### 原因 2：函数缺少 JSDoc 注释（占 ~50 条）

### 为什么数量如此庞大

一句话：**lint 配置文件和代码是两批不同时期产生的**。

```
时间线:
  早期  → 写了全部 js/ 代码，用 let，没 JSDoc（没有 lint）
  ↓
  合并  → 工作区引入了 .eslintrc.json + package.json（lint 配置）
  ↓
  现在  → CI 第一次跑 lint，把 192 个历史代码风格问题一次性照出来
```

lint 配置是后来（合并阶段）才加入的，代码从未针对这些规则做过适配，所以**历史欠债一次性暴露**。
